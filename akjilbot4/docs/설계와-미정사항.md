# 악질봇 4.0.0 설계와 미정사항

> 과거 설계 기록이다. 현재 탐험 구현·운영 설정은 [README](../README.md), 적용한 기본 해석과 이후 유물·상점 입력 사항은 [입력할 설정](입력할-설정.md)을 우선한다.

> 초기 설계에서 이어진 기록이다. 영웅 선택·두 메인 페이즈·손패 8장·초과 손패 제외·신규 카드·상대의 최신 결정은 [추가 확정 규칙](확정규칙-2026-10-02.md)을 우선한다.

이 문서는 사용자가 확정한 규칙을 기준으로 한 제작 명세다. 카드·보스·유물과 미정 수치는 실제 운영 데이터로 임의 확정하지 않는다. 구현 시 사용하는 임시 처리 순서는 아래에서 별도로 구분한다. 이 문서 자체는 실제 봇 환경의 배포 또는 장애 복구 검증 결과를 의미하지 않는다.

현재 거프와 기본 덱 효과, 상대 18종의 덱·능력 명세는 등록했다. 나머지 카드 효과·보스 전투 처리·보물·유물 등이 미완료여서 `enabled: false`다. 자세한 구현 범위는 [README](../README.md)에 기록한다.

## 1. 제작 범위

- 기존 대전, 랭크, 시즌, 기존 전적은 탐험으로 완전히 대체한다.
- 4.0.0은 새 데이터로 시작한다. 3.1.0이나 2.8.5의 돈, 카드, 유물, 사용자 기록을 가져오지 않는다.
- 3.1.0은 채팅 전투 화면, 카드 발동 멘트, 상성 처리, 일부 카드·보스의 참고 자료다. 전체 게임을 복사한 뒤 규칙 일부만 바꾸는 것이 아니다.
- 2.8.5는 유물 강화 처리와 화면의 참고 자료다. 기존 강화 비용·확률·최고 강화 수치는 4.0.0에 자동 적용하지 않는다.
- 유저마다 진행 중 탐험은 최대 1개다. 탐험, 인벤토리, 유물 등 모든 유저 데이터는 허용된 방 사이에서 공유한다.
- 실제 운영 방 2개와 테스트 방 3개를 사용한다. 정확한 방 이름은 아직 확인이 필요하다.

## 2. 탐험과 세션

`탐험`은 영웅 선택부터 패배·포기·8승 정산까지 이어지는 전체 진행이다. `세션`은 지금 채팅에서 전투나 보상 선택을 진행하는 구간이다. 세션 종료는 탐험 패배나 정산을 의미하지 않는다.

1. 진행 중 탐험이 없는 상태에서 `+탐험`을 입력한다.
2. 새 탐험과 영웅 선택지를 생성하면서 미궁 열쇠 1개를 함께 차감·저장한다.
3. 영웅을 선택한다. 현재 거프의 기본 덱은 8장이고 시작 손패는 4장이다. 선택 중 재시작해도 추가로 차감하지 않는다.
4. 현재 단계의 상대와 전투한다.
5. 승리하면 단계별 보상 선택과 덱 수정을 진행한다.
6. 보상 선택을 모두 마치면 세션을 끝내고 다음 전투 직전 상태로 저장한다.
7. 이후 `+탐험`을 입력하면 다음 상대와 전투한다.
8. 패배·포기하거나 8번째 상대를 쓰러뜨리면 탐험을 종료하고 누적 처치 수의 보상을 한 번 정산한다.

전투 중이나 보상 선택 중 세션이 중단되었다면 `+탐험`은 저장된 단계를 이어간다. 아직 끝내지 않은 전투를 건너뛰거나 보상 선택을 새로 뽑지 않는다. 중단 후 재개에는 열쇠를 추가로 소모하지 않는다.

- `gg`: 진행 중인 탐험 포기. 그 시점의 처치 수 기준으로 정산한다.
- 일정 시간 무응답: 세션 종료 후 저장. 나중에 재개할 수 있다. 제한 시간은 미정이다.
- 양쪽 동시 사망: 탐험 실패. 최종 상대와 동시 사망해도 클리어로 보지 않는다.
- 탐험마다 총 8명의 상대를 상대한다. 뒤 단계일수록 상대 체력과 덱이 강해진다.
- 전투마다 체력을 완전히 회복하고 일반 전투 상태를 초기화한다. 보호막·상태 이상·전투 중 생성 카드 등도 원칙적으로 다음 전투에 유지하지 않는다.
- 탐험 전체에 적용된다고 명시한 효과와 보상 단계의 덱 변경은 탐험이 끝날 때까지 유지한다.
- 턴 번호와 마나는 매 전투의 0턴부터 다시 시작한다.

## 3. 전투의 카드 영역

| 영역 | 의미 | 다음 전투 유지 |
| --- | --- | --- |
| 탐험 덱 | 탐험에서 실제로 보유한 카드 목록. 카드별 개체 식별자를 가진다. | 유지 |
| 뽑을 카드 | 이번 전투에서 아직 손패로 가져오지 않은 카드 | 유지하지 않음 |
| 손패 | 이번 턴에 제출할 수 있는 카드. 기본 최대 8장 | 유지하지 않음 |
| 제출 영역 | 일괄 제출 후 이번 턴의 상성·효과 처리를 기다리는 카드 | 유지하지 않음 |
| 레스트 | 사용한 카드가 들어가는 영역. 뽑을 카드가 없으면 재사용 | 유지하지 않음 |
| 제외 영역 | 이번 전투에서 일반적으로 되돌아오지 않는 카드의 보관 영역 | 유지하지 않음 |

### 드로우와 레스트

- 0턴 시작 손패는 덱에서 무작위 4장이다. 0턴에는 기본 드로우를 추가하지 않는다.
- 1턴부터 매 턴 시작 시 카드 1장을 뽑는다.
- 사용하지 않은 손패는 다음 턴에도 남는다.
- 손패가 8장이어도 드로우를 처리하고 초과한 카드는 게임에서 제외한다.
- 드로우·생성·회수 등 어떤 경로도 손패 8장을 초과할 수 없다.
- 손패 8장에서 2장 드로우 카드를 쓰면 사용한 카드가 먼저 손패에서 빠지므로, 다른 변화가 없다면 1장은 손패에 들어오고 나머지 1장은 제외된다.
- 뽑을 카드가 없으면 레스트의 카드가 뽑을 카드 영역으로 이동하고 드로우를 이어간다.
- 손패·제출 영역·제외 영역의 카드를 복제해서 리필하지 않는다.
- 뽑을 카드와 레스트가 모두 비었다면 뽑을 수 있는 카드가 생길 때까지 추가 드로우는 없다. 이 사실 자체로 피해를 받지 않는다.
- 한도를 초과해 뽑은 카드는 레스트에 버리지 않고 제외한다.

**초기 구상의 ‘전투 시작 덱 전체 리필’은 사용자의 최종 결정으로 폐기되었다. 반드시 레스트만 재사용한다.**

### 사용·변경·제외·영구 제거

- 일반 카드 사용: 마나를 지불하고 손패에서 빠진 뒤 레스트로 이동한다.
- 카운터당한 카드도 지불한 마나와 카드가 돌아오지 않는다.
- 전투 중 생성·변경·강화된 카드는 기본적으로 해당 전투에만 적용한다. 다음 전투는 탐험 덱을 기준으로 새로 만든다.
- `제외`: 레스트로 이동하지 않고 별도 제외 영역으로 이동한다. 보통의 리필로 다시 돌아오지 않는다. 다음 전투에는 영향을 주지 않는다.
- `탐험 덱에서 제거`: 해당 전투뿐 아니라 탐험 덱에서도 선택한 카드 개체를 제거한다. 다음 전투에도 반영한다.
- 같은 이름의 카드 여러 장은 서로 다른 개체다. 한 장을 강화·제거하면 선택한 그 한 장만 바뀐다.
- 카드형 보물은 일반적인 강화·제거의 대상이 아니다. 명시된 보물 교체만 가능하다.

## 4. 턴, 마나, 제출, 상성

### 마나

| 턴 | 최대 마나 |
| --- | ---: |
| 0~4 | 1 |
| 5~9 | 2 |
| 10~14 | 3 |
| 15~19 | 4 |
| 20 이후 | 5 |

기본 최대 마나는 `min(5, 1 + floor(턴 / 5))`이다. 매 턴 시작에 현재 최대 마나까지 충전한다. 전투 화면은 전체 마나 칸과 남은 마나를 함께 표시한다. 예를 들어 최대 3 중 1이 남았으면 `🔵⚪⚪ (1/3)`처럼 표현할 수 있다. 구체적인 이모지는 화면상의 선택이며 밸런스 규칙은 아니다.

### 일괄 제출

- 플레이어는 그 턴에 사용할 카드들을 모아 한 번에 제출한다.
- 현재 마나 범위 안에서 여러 장을 제출할 수 있다.
- 상대도 손패·드로우·마나·레스트 규칙을 동일하게 적용한다.
- 상대는 플레이어의 현재 제출을 보기 전에 자기 제출을 확정한다.
- 상대는 자신의 정보와 공개된 정보로 플레이어의 행동을 예측한다. 숨겨진 플레이어 손패, 다음 드로우 순서, 아직 제출하지 않은 입력을 읽지 않는다.
- 봇 종료·세션 재개를 이유로 이미 결정된 상대 제출을 바꾸지 않는다.
- 여러 카드의 상성 처리는 3.1.0의 양쪽 제출 카드 비교 방식을 참고한다.
- 카운터당한 카드의 일반 효과는 모두 무효다. 마나와 카드는 그대로 소모된다.

일괄 제출을 선택한 결과, 제출 확정 뒤 효과로 새로 뽑은 카드는 그 턴의 제출에 소급해서 추가하지 않는다. **현재 제작 기준에서는 다음 턴부터 제출 가능**으로 해석한다. 사용자가 별도의 추가 제출 창을 원하면 턴 규칙을 변경해야 한다.

### 아직 사용자에게 확정받지 않은 처리 순서

다음은 구현을 서로 일관되게 만들기 위한 기본 처리안이며 사용자의 확정 발언과 구분한다.

1. 선택 카드 전체의 존재 여부·중복 선택·마나를 먼저 검증한다. 잘못된 입력으로 일부 카드만 소모하지 않는다.
2. 양쪽 제출 카드를 손패에서 빼고 비용을 소모한다.
3. 제출 영역에 있는 카드 전체로 상성을 판정한다.
4. 카운터당하지 않은 양쪽 카드의 회복·보호막 효과를 먼저 처리하고, 나머지 효과는 플레이어 쪽 제출 순서, 상대 쪽 제출 순서로 처리한다.
5. 처리가 끝난 제출 카드를 레스트 또는 제외 영역으로 이동한 뒤 양쪽 사망 여부를 확인한다. 도중 한쪽 체력이 0 이하가 되었다는 이유만으로 이미 제출된 상대 효과를 생략하지 않는다.
6. 전투가 계속되면 다음 턴으로 이동해 마나 충전, 장기전 피해와 사망 확인, 드로우, 상대 제출 확정을 순서대로 수행한다.

이 기본안에서는 **현재 해결 중인 제출 카드는 드로우 효과로 즉시 다시 뽑히지 않는다.** 제출 카드가 손패에서 빠지는 것과 레스트에 도착하는 것은 별개의 단계다. 제출 카드가 언제 레스트로 이동하는지, 피해·회복·방어·사망 판정의 세부 순서는 카드 효과를 확정할 때 함께 검토할 항목이다. 구현의 실제 기본값이 달라지면 이 절을 맞춰 수정해야 한다.

기본 보호막은 턴이 넘어가도 남고, 다음 전투 시작 때 초기화하는 것을 제작 기본안으로 삼는다. 보호막의 턴 종료 소멸을 원한다면 명시적인 규칙 또는 해당 카드 효과로 추가해야 한다.

여러 상대 카드가 같은 카드를 카운터했을 때의 보너스 발동 횟수도 일반 카드 채택에 따라 정의해야 한다. 사용자가 ‘카운터 시’ 효과의 횟수를 별도로 확정하지 않았으므로, 모든 부가 효과를 임의로 ‘카드당 1회’로 변경했다고 간주하지 않는다. 관련 카드·보물은 이 규칙이 정의되어야 활성화한다.

### 장기전 피해

- 30턴부터 매 턴 양쪽에 장기전 피해를 준다.
- 30~34턴: 1, 35~39턴: 2, 40~44턴: 3이며 이후도 5턴마다 1씩 증가한다.
- 피해량은 30턴 이상일 때 `1 + floor((턴 - 30) / 5)`이다.
- 덱이나 레스트에 남은 장수와 무관하다.
- 이 피해로 동시 사망하면 탐험 실패다.
- 현재 제작 기본안은 **새 턴 시작에 드로우 전에 적용하며 보호막을 무시하는 피해**다. 29턴 해결 후 30턴이 시작될 때 첫 1피해가 발생한다. 이 세부 해석은 사용자에게 최종 확인할 항목이다.

## 5. 승리 후 탐험 보상 단계

| 승리 | 먼저 처리할 단계 | 이후 일반 카드 추가 |
| --- | --- | --- |
| 1승 | 하급 보물 3개 중 1개 획득 | 일반 카드 3개 중 1개 선택을 2회 |
| 2승 | 덱에서 무작위로 제시되는 강화 가능 카드 3장 중 1장 강화 | 일반 카드 선택 2회 |
| 3승 | 제거 여부 결정. 수락하면 덱에서 무작위로 제시되는 4장 중 1장 제거 | 일반 카드 선택 2회 |
| 4승 | 상급 보물 3개 중 1개 획득 | 일반 카드 선택 2회 |
| 5승 | 2승과 같은 강화 | 일반 카드 선택 2회 |
| 6승 | 아래 보물 교체 3가지 중 선택 | 일반 카드 선택 2회 |
| 7승 | 아래 덱 수정 3가지 중 선택 | 선택한 덱 수정에 포함된 추가만 진행 |
| 8승 | 탐험 성공과 최종 재화 정산 | 없음 |

### 6승 보물 교체

1. 하급 보물을 무작위 상급 보물로 교체한다.
2. 제시되는 상급 보물 3개 중 1개를 선택하여 기존 상급 보물을 교체한다.
3. 아무 행동도 하지 않는다.

### 7승 덱 수정

1. 카드 2장 제거 후 카드 2장 추가.
2. 카드 2장 제거.
3. 카드 2장 추가.

제거는 매번 남은 덱에서 제시되는 무작위 4장 중 한 장을 선택하는 방식이다. 추가는 매번 제시되는 3장 중 한 장을 선택하는 방식이다. 첫 선택 결과를 반영한 뒤 다음 선택지를 만들어 저장한다.

### 선택 공통 규칙

- 한 번 제시되는 일반 카드 3칸에 같은 카드 정의가 중복해서 나오지 않는다.
- 이미 탐험 덱에 가진 카드는 제시될 수 있다. 바로 앞 추가 단계에서 고른 카드도 다음 추가 단계에는 다시 나올 수 있다.
- 강화·제거는 실제 보유 카드 개체를 대상으로 하므로 같은 이름의 보유 카드 여러 장을 구분해야 한다.
- 일반 카드의 강화는 한 장당 한 번만 가능하다. 강화 후 이름에 `+`를 붙인다.
- 강화 선택지에는 기존 효과와 강화 효과를 모두 보여준다.
- 이미 강화한 카드와 보물은 강화 후보에서 제외한다.
- 강화 가능한 카드가 없으면 강화 단계를 건너뛴다.
- 보물은 일반 제거 후보에서 제외한다.
- 강화·제거 대상이 제시 수보다 적으면 실제 가능한 대상만 제시하는 것을 제작 기본안으로 삼는다.
- 거절 선택지가 사용자의 흐름에 명시된 경우에만 거절 가능하다. 일반 카드 추가·보물 획득·가능한 강화는 필수다.
- 선택 도중 종료되더라도 이미 제시된 선택지, 대상 카드 식별자, 진행 순서는 그대로 복원한다.
- 후보 데이터가 아예 부족한 것은 콘텐츠 설정 오류다. 무작위 가짜 카드나 보물을 넣어 진행하지 않는다.

## 6. 보물

보물은 해당 탐험 동안만 유지하며 하급·상급으로 구분한다.

| 유형 | 덱에 포함 | 드로우·사용 | 작동 방식 |
| --- | --- | --- | --- |
| 카드형 | 포함 | 가능 | 손패에서 비용을 지불해 사용 |
| 지속 효과형 | 포함하지 않음 | 불가능 | 사용하지 않아도 탐험 동안 해당 효과 적용 |

- 같은 보물은 중복 보유할 수 없다.
- 하급 보물 1개와 상급 보물 1개를 가진 상태에서 6승 보상의 첫 선택을 하면 상급 보물 2개가 된다.
- 카드형과 지속 효과형 사이의 교체도 가능하다. 교체 시 기존 보물을 제거하고 새 유형에 맞게 덱 또는 지속 효과 목록에 반영한다.
- 카드형 보물을 지속 효과형으로 바꾸면 덱 장수가 한 장 줄 수 있으며, 반대면 한 장 늘 수 있다.
- 거프의 8장 덱은 첫 승리의 카드 보상 2장으로 10장이 된다. 카드형 하급 보물을 골랐다면 총 덱은 11장이고, 지속 효과형을 골랐다면 덱 10장과 지속 효과 1개다. 전투 중 탐험 덱을 변경하는 효과는 별도로 반영한다.
- 보물 후보를 구성할 때 현재 가진 동일 보물을 새 보상으로 중복 지급하지 않는다.

## 7. 탐험 종료 재화 보상

보스마다 재화를 즉시 주는 방식이 아니다. **탐험 종료 시 최종 처치 수 한 행만 적용하여 한 번 지급**한다. 8승 보상에 이전 0~7승 행을 누적 합산하지 않는다. 포기도 현재 처치 수를 기준으로 정산한다.

골드는 아래 범위의 50G 단위 값만 나온다. 아직 별도 가중치가 없으므로 같은 범위의 50G 후보를 균등 추첨하는 것을 제작 기본안으로 삼는다. 재료 항목 간 추첨은 별도 추첨을 기본안으로 삼으며 사용자 지시가 있으면 가중치·상관관계를 변경한다.

| 최종 승수 | 골드 | 미궁 열쇠 | 강화석 | 정수 |
| --- | --- | --- | --- | --- |
| 0 | 50G | 없음 | 없음 | 없음 |
| 1 | 50~100G | 없음 | 없음 | 없음 |
| 2 | 100~200G | 없음 | 없음 | 없음 |
| 3 | 200~400G | 없음 | 없음 | 없음 |
| 4 | 200~400G | 1개 20%, 0개 80% | 없음 | 없음 |
| 5 | 400~600G | 1개 80%, 0개 20% | 0개 80%, 1개 20% | 없음 |
| 6 | 500~800G | 1개 100% | 1개 80%, 2개 20% | 없음 |
| 7 | 600~1000G | 1개 100% | 2개 60%, 3개 40% | 0개 50%, 1개 50% |
| 8 | 1000~1500G | 1개 100% | 3개 60%, 4개 30%, 5개 10% | 1개 70%, 2개 20%, 3개 10% |

정수의 구체적인 사용처는 아직 정하지 않았다. 재화로 저장·표시할 수 있지만 임의의 소비 기능을 만들지 않는다.

## 8. 미궁 열쇠 자동 획득

- 새 탐험에는 열쇠 1개가 필요하다.
- 탐험 중에는 자동 충전하지 않는다. 탐험 종료(클리어·패배·포기) 시점부터 30분마다 1개씩 자동 획득한다. 탐험을 잠시 중단하거나 봇을 재시작해도 진행 중인 탐험이 있으면 충전하지 않는다.
- 자동 획득으로는 최대 5개까지만 보유한다.
- 5개 이상이면 자동 획득하지 않는다.
- 탐험 보상, 유물, 기타 보상으로는 5개를 초과해 보유할 수 있다.
- 세션 종료·봇 재시작 때문에 충전 기준 시각이 초기화되어서는 안 된다.
- 재개한 탐험에 열쇠를 다시 청구하지 않는다.

제작 기본안은 저장된 충전 기준 시각과 실제 경과 시간을 사용하여, 봇이 꺼져 있던 시간도 복귀 시 계산하는 것이다. 5개 이상인 동안 충전 시간을 추가 열쇠로 적립하지 않고, 탐험 중에는 충전을 멈추고, 탐험 종료 시점부터 새로 30분을 계산한다. 탐험이 없는 동안에는 저장된 기준 시각을 사용하여 오프라인 경과 시간도 반영한다.

## 9. 유물, 강화, 상점

### 보유와 장착

- 유물 등급: C, B, A, S, SS.
- 같은 유물을 여러 개 보유할 수 있다. 각 보유 유물은 개별 식별자와 강화 수치를 가진다.
- 같은 종류의 유물을 여러 개 동시에 장착할 수는 없다.
- 최초 장착 슬롯은 1개이며 최대 3개로 확장한다.
- 2번째·3번째 슬롯 확장에는 많은 골드와 강화석이 필요하다. 비용은 미정이다.
- 진행 중인 탐험이 있으면 장착 유물을 변경하지 못한다. 세션이 중단된 탐험도 진행 중 탐험에 포함된다.
- 탐험 중에도 강화는 가능하며 그 결과는 진행 중인 탐험에도 반영한다. 탐험 시작 당시 강화 수치를 고정하는 방식은 사용하지 않는다.

### 강화

- 최고 강화: +5.
- 모든 등급에서 대성공은 없다.
- C·B·A: 성공, 실패, 하락만 존재한다. 파괴는 없다.
- S·SS: 성공, 실패, 하락에 파괴 가능성도 존재한다.
- 2.8.5의 결과 의미를 참고하여 성공은 +1, 실패는 유지, 하락은 -1, 파괴는 해당 유물 개체 제거를 기본안으로 한다. +0에서 음수 강화는 허용하지 않는다.
- 등급별·현재 강화 단계별 골드/강화 재료 비용 및 성공·실패·하락·파괴 확률은 미정이다.
- 확률 합은 각 표의 행마다 100%여야 한다. C·B·A는 파괴 0%, 모든 등급은 대성공 0%를 검증한다.
- 비용은 결과와 무관하게 시도 시 소모하는 2.8.5 방식을 참고하되, 정확한 비용표가 채워져야 운영 강화가 가능하다.
- +5 유물에는 추가 강화 시도를 받지 않는다.

탐험 중 장착 유물 강화가 즉시 적용된다는 규칙은 확정되었지만 다음 세부 결과는 아직 비어 있다.

1. 최대 체력 효과가 증가·감소했을 때 현재 체력을 어떻게 바꿀지.
2. 마나·손패 한도 등이 바뀌었을 때 이미 진행 중인 턴을 어떻게 보정할지.
3. 턴 시작이나 전투 시작에 한 번 적용되는 효과를 강화 직후 다시 적용할지.
4. 장착한 S·SS 유물이 파괴되면 빈 슬롯을 유지할지와 진행 중 탐험의 효과 제거 시점.
5. 강화 하락도 진행 중 탐험에 즉시 약화 효과를 줄 때 구체적으로 어떻게 보정할지.

**위 해석이 필요한 유물은 처리 규칙 없이 임의 적용하지 않는다.** 해당 유물의 관련 행동만 설정 미완성으로 막고 비용을 차감하지 않는 방향으로 구현해야 한다. 유물 정의마다 실시간 갱신 방법을 지정하면 일반적인 강화 기능은 진행할 수 있다.

엔진에 준비하는 제작 기본안은 최대 체력이 증가해도 현재 체력을 공짜로 회복하지 않고, 최대 체력이 줄면 현재 체력이 새 최대치를 초과하지 않도록 제한하는 것이다. 전투 시작 보호막 같은 일회성 보너스를 강화 직후 다시 주지 않으며, 상대의 이미 확정된 행동도 다시 고르지 않는다. **이것은 사용자 확정 규칙이 아니므로 유물의 실제 효과를 채울 때 함께 확인해야 한다.** 장착 유물 파괴 처리 설정이 비어 있으면 탐험 중 해당 파괴 가능 강화를 막는다.

### 상점과 명령어

- 저렴하고 낮은 희귀도가 주로 나오는 유물 뽑기와, 비싸고 높은 희귀도를 기대할 수 있는 뽑기가 존재한다.
- 각 뽑기의 가격, 등급 확률, 등급 안에서 등장하는 유물 목록/가중치는 미정이다.
- 뽑기 중복은 새 유물 개체로 보유한다. 임의로 강화석으로 바꾸지 않는다.
- `+인벤`: 돈, 미궁 열쇠, 강화석, 정수 및 기타 확정된 아이템 표시.
- `+유물`: 보유 유물별 등급·강화 수치·장착 상태 표시와 장착 선택.
- 뽑기·강화·슬롯 확장의 세부 명령 문법은 화면과 함께 정할 수 있는 구현 항목이다.
- 판매·분해·거래·강화 보호 주문서·천장·유물 진화는 아직 요청되지 않았다. 2.8.5에 있더라도 자동 도입하지 않는다.

## 10. 방 공유와 사용자 식별

확인한 3.1.0의 `ALLOWED_ROOMS`는 실제로 `옥랜111`, `옥랜222`, `개발123` 세 개다. 따라서 ‘운영 2개 + 테스트 3개’라는 현재 요구를 기존 배열 그대로 가져와 만족했다고 볼 수 없다. 총 다섯 방의 정확한 이름을 받아야 한다.

3.1.0에는 메시지의 사용자 해시 등을 읽고, `+연동코드`와 `+연동`으로 방별 식별자를 하나의 유저에 연결하는 구조가 있다. 4.0.0 역시 플랫폼이 모든 방에서 같은 안정적인 식별자를 제공한다면 이를 공통 키로 사용하고, 방별로 다르면 명시적 연결 방식이 필요하다.

- 닉네임이 같다는 이유만으로 데이터를 합치지 않는다.
- 사용자의 닉네임 변경은 계정 생성이나 계정 병합 근거가 아니다.
- 기존 버전의 연동 기록도 자동으로 이관하지 않는다.
- 두 식별자에 이미 서로 다른 4.0.0 데이터가 있다면 어느 데이터를 남길지 정하지 않고 자동 병합하지 않는다.
- 모든 방에서 진행 중 탐험 1개, 재화, 장착 유물 상태를 같은 데이터 기준으로 처리한다.
- 여러 방에서 동시에 보낸 선택 입력이 한 보상이나 한 재화를 중복 사용하지 않게 해야 한다.

실제 메시지의 안정적인 사용자 식별 필드, 테스트 방 이름, 연동 허용 방 범위가 최종 확인 대상이다. 사용자 동의 없는 닉네임 추정 연결은 그 대안이 아니다.

## 11. 갑작스러운 종료에 대한 저장 요구사항

다음은 필요한 동작과 검증 기준이다. 구현이 존재한다는 사실만으로 실제 저장 매체 고장까지 막는다고 주장해서는 안 된다.

### 반드시 저장할 내용

- 유저 재화, 열쇠 충전 기준 시각, 보유 유물 개체와 강화 수치, 슬롯 수, 장착 상태.
- 탐험 식별자, 기본 덱 선택, 남은 탐험 덱, 보물, 처치 수, 현재 단계.
- 진행 중 전투의 상대, 턴, 양쪽 체력·마나·일반 상태·카드의 모든 영역.
- 상대가 이미 결정한 제출과 무작위 결정 결과.
- 현재 선택지와 개별 대상 식별자, 보상 선택 순서와 남은 단계.
- 세션 중단/활동 시각. 세션이 끊겨도 탐험 자체는 남아야 한다.
- 최종 정산 대상과 실제 지급 결과, 해당 탐험이 이미 지급되었다는 정보.
- 상점·강화·슬롯 확장의 비용과 결과가 확정된 상태.
- 방별 사용자 식별 연결.

아래 변경은 한 묶음으로 저장되어야 한다. 일부만 적용된 상태로 재개하면 안 된다.

| 처리 | 같은 저장 단위에 포함할 변화 |
| --- | --- |
| 탐험 시작 | 열쇠 1개 차감 + 탐험 생성 |
| 턴 제출 | 양쪽 비용·카드 이동 + 효과·드로우·상태 + 다음 턴 또는 전투 종료 |
| 보상 선택 | 선택 결과 반영 + 다음 선택지/단계 확정 |
| 최종 정산 | 확정 보상 지급 + 해당 탐험 정산 완료 |
| 강화 | 비용 차감 + 확률 결과 + 유물 변화 + 진행 중 탐험 영향 |
| 뽑기 | 골드 차감 + 추첨 결과 + 새 보유 유물 개체 |
| 슬롯 확장 | 골드/강화석 차감 + 슬롯 수 증가 |
| 열쇠 회복 | 획득 수량 + 충전 기준 시각 갱신 |

저장 성공 전에는 사용자에게 ‘완료’, ‘보상 지급’, ‘강화 성공’ 같은 확정 응답을 보내지 않는 것이 원칙이다. 저장이 실패하면 성공 처리하거나 메모리에서만 진행하지 않는다. 응답 전송은 외부 채팅 시스템의 동작이므로 저장 직후 봇이 꺼져 메시지만 누락될 수 있다. 이 경우 다시 상태를 조회해서 확인할 수 있어야 하고, 이미 저장된 보상을 또 지급해서는 안 된다.

### 복구 기준

- 마지막 정상 저장 이후 기록을 복구할 수 있도록 변경 기록과 유효한 기준 저장본을 관리한다.
- 재시작 시 저장 형식 버전과 무결성을 확인한다. 파일이 깨졌다고 빈 신규 계정으로 덮어쓰지 않는다.
- 저장 도중 끊긴 마지막 불완전 기록과 그 앞의 정상 기록을 구분한다. 중간 기록이 손상된 경우 무조건 무시하고 진행하지 않는다.
- 복구 가능한 저장본/기록이 없으면 운영을 중단하고 원본을 보존한다.
- 저장 결과와 기록 순서를 확인할 수 있어야 하며, 중요 단계의 저장 실패를 숨기지 않는다.
- 동시에 여러 명령이 들어와도 저장 순서가 꼬이지 않도록 처리한다.
- 백업은 저장 장치 자체의 고장에 대비하는 별도 수단이다. 같은 장치에 복사한 파일만으로 장치 분실·파괴까지 방어했다고 말하지 않는다.

### 필요한 검증

- 열쇠 차감 뒤 강제 종료, 최종 보상 저장 중 강제 종료, 보상 선택 직후 강제 종료.
- 턴 중 손패·레스트·제외 카드의 중복/유실 여부와 재개 시 마나·드로우 일치.
- 강화/뽑기 비용과 결과가 일부만 남지 않는지.
- 이미 확정한 상대 제출·선택지·보상 추첨이 재시작으로 바뀌지 않는지.
- 로그 끝이 잘린 경우, 저장 파일이 손상된 경우, 저장 실패를 주입한 경우.
- 여러 방에서 같은 계정에 연속 입력했을 때 중복 정산이나 열쇠 이중 소모가 없는지.

파일 동기화·원자적 교체·디렉터리 저장 동작은 실제 봇 런타임과 파일 시스템의 지원을 확인해야 한다. 로컬 단위 테스트의 통과와 Android/실제 봇에서 전원 종료 후 검증한 결과는 구분해서 보고한다.

## 12. 사용자가 다음에 제공하면 되는 내용

### 운영 콘텐츠

| 항목 | 필요한 값 |
| --- | --- |
| 일반 카드 | 채택할 카드, 속성, 비용, 기본 효과, 강화 효과, 발동 멘트, 명시적 예외 |
| 기본 덱 | 선택 가능한 덱 이름과 각 4장의 카드 구성 |
| 플레이어 | 기본 최대 체력 및 기본 덱마다 다른지 여부 |
| 상대 1~8단계 | 이름, 최대 체력, 덱, 특수 효과, 고정 상대/후보 풀 여부 |
| 하급/상급 보물 | 이름, 등급, 카드형/지속 효과형, 비용/효과, 중복 판단 기준 |
| 유물 | 이름, C/B/A/S/SS 등급, +0~+5 효과, 실시간 강화 반영 방법 |

콘텐츠가 없는 슬롯은 비워 둔다. 테스트용 카드를 사용하더라도 실제 보상 풀·기본 덱·보스 데이터와 섞지 않는다.

### 경제 및 운영 설정

1. C/B/A/S/SS의 현재 +0~+4별 강화 비용과 성공·실패·하락·파괴 확률. 단계별 합계는 100%이며 대성공은 없다.
2. 2번째·3번째 슬롯의 골드/강화석 비용.
3. 저가·고가 유물 뽑기 이름, 골드 가격, 등급 확률, 등장 유물과 가중치.
4. 새 유저의 최초 골드·열쇠·재료·유물 지급량. ‘별도 데이터로 시작’이 ‘열쇠 0개로 시작’을 뜻하지는 않으므로 미정으로 둔다.
5. 무응답으로 세션을 닫을 시간.
6. 운영 2개·테스트 3개 방의 정확한 이름과 실제 메시지의 안정적인 사용자 식별자.
7. 방별 식별자가 다를 때 연동 코드 허용 범위와, 연결 대상에 기존 데이터가 있는 경우의 처리.
8. 실제 봇 실행 환경, 사용 가능한 영속 저장 경로와 API. 이는 배포/저장 검증에 필요하다.

### 규칙의 남은 세부 해석

1. 제출 카드의 레스트 이동 시점, 양쪽 효과 해결·사망 확인 순서, 여러 카운터 보너스의 발동 횟수.
2. 장기전 피해의 적용 시점과 보호막 등 방어 효과의 적용 여부.
3. 진행 중 탐험에서 유물 강화·하락·파괴가 현재 체력·마나·손패 한도·단발 효과를 갱신하는 방법. 파괴된 장착 슬롯에 탐험 도중 다른 유물을 끼울 수 있는지는 장착 변경 금지와 함께 명시해야 한다.
4. 자동 열쇠 충전의 만충 후 재시작 시계, 종료 보상 골드 범위 안의 균등 확률과 항목별 독립 추첨이 의도와 맞는지.

이 항목들은 빠진 정보를 과거 코드에서 확인할 수 있으면 그 근거를 적어 사용하고, 4.0.0 규칙과 충돌하거나 근거가 없으면 빈 설정 또는 명시된 제작 기본안으로 남긴다. 운영에 꼭 필요한 값이 비었을 때 비용부터 차감하거나 임의 콘텐츠로 진행하는 방식은 사용하지 않는다.
