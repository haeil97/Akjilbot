# 악질봇 4.0.0

카카오톡봇에는 루트의 **`악질봇4.0.0.js` 하나**를 등록한다. MessengerBotR API2의 BotManager, Event.MESSAGE, Java 파일 API를 사용한다. 휴대폰에 Node.js나 개발용 파일을 따로 설치할 필요가 없다.

탐험을 활성화했다. 정의된 직업 6종(거프 룬토템·사일런트·운룡 셀레스테·대사제 데칼·아감마간·노틸러스)을 포함한다. 현재 새 탐험에서는 거프만 선택창에 표시하며 다른 5개 직업은 일시 비활성화했다. 중립 카드 108종, 상대 26종, 중립 보물 62종과 직업·시작 보물이 구현되어 있다. 전투 후 카드 묶음 선택 → 휴식·제련 → 이벤트 → 선술집으로 진행하며 이벤트 내용은 준비 중이다. 계정 재화는 코인(C), 탐험 재화는 골드다.

- 운영 방: `옥랜111`, `옥랜222` / 테스트 방: `개발123`.
- `+탐험`: 새 탐험 또는 진행 재개. 새 탐험에서만 열쇠 1개 사용.
- 매 전투 시작 전 상대 이름·체력·영웅 능력과 `y / n`을 표시한다. 1분 안에 `y`를 입력하면 전투를 시작한다. `n` 또는 시간 초과는 세션만 종료하며, `+탐험`으로 같은 상대의 확인 화면을 다시 연다. 이미 시작한 전투를 재개할 때는 확인하지 않는다.
- `1`: 영웅·보상·발견 화면에서 1번 선택. 번호 하나만 입력한다.
- `1 3`: 전투에서 손패 1번과 3번 일괄 제출.
- `0 2 1`: 영웅 능력(0번)과 손패 2번, 1번 제출. `0`만 쓰면 능력만 사용.
- `s`: 이번 페이즈 쉬기. `gg`: 포기 후 현재 승수 정산.
- `+인벤`, `+ㅇㅂ`: 골드·아이템·열쇠 자동 획득 시간.
- `+덱`, `+도움말`: 덱과 보물, 명령어.

관리자 명령은 `++관리자획득`, `++아이템지급 [닉네임] [아이템명] [수량]`, `++아이템회수 [닉네임] [아이템명] [수량]`이다. 요청한 예외에 따라 누구나 `++관리자획득`으로 자신의 계정에 권한을 얻을 수 있다. 나머지 `++` 명령은 관리자만 사용할 수 있다. 아이템명은 `골드`, `미궁 열쇠`(`미궁열쇠`도 가능), `강화석`, `정수`를 지원한다. 수량은 양의 정수이며, 회수량이 보유량보다 많으면 변경하지 않는다. 공백이 있는 닉네임도 그대로 입력할 수 있고, 동명이인이면 중단한다. 대상은 봇에 등록된 계정이어야 한다. 지급 열쇠는 5개를 넘길 수 있다. 권한·재화 변경·명령 응답은 함께 저장하며 최근 관리자 변경 256건을 별도로 보관한다.

일시정지(p)가 가능한 전투에서는 입력 시간 초과도 p와 같이 처리한다. 세션과 마감 시간만 종료하고 현재 페이즈·손패·상대 계획·발견 선택지를 보관하며, +탐험으로 재개한다. 일반 메인 페이즈와 발견·인양·속성 선택의 제한은 2분 30초, 램프 검색은 2분이다. 램프도 선택 진행을 보관하고 재개할 때 검색 시간을 다시 부여한다. 백야처럼 p가 금지된 전투는 기존처럼 메인 페이즈 시간 초과 시 빈 제출(s), 선택 시간 초과 시 무작위 선택으로 진행한다. 전투 외 단계는 무응답 1분 후 세션만 종료하고 진행은 보관한다. 보상 단계에서 s를 입력하면 선택지를 그대로 보관하고 즉시 세션을 종료한다. 봇 재시작 시 세션을 정지하고 +탐험으로 재개한다.

한 방에는 활성 탐험 세션을 하나만 허용한다. 영웅 선택·전투 시작 확인·전투·보상 선택 중에도 방을 점유한다. 해당 유저 본인은 입력할 수 있고, 다른 일반 유저의 모든 명령은 응답 없이 무시한다(`++관리자획득` 포함). 다른 관리자는 일반·관리 명령만 사용할 수 있으며 탐험 시작·재개, 숫자 선택, 카드 제출, y/n, s, gg는 차단한다. 소유자는 닉네임이 아니라 저장된 계정 ID로 판별한다. 다른 방은 독립적으로 사용할 수 있다. 세션 종료·만료·재시작·다른 빈 방으로 이동 시 기존 방의 점유를 해제하며 탐험 기록은 유지한다.

탐험 종료 화면은 `⚔️ 탐험 - 결과 ⚔️` 아래에 상대별 처치 성공(✅️)·실패(❌️)를 만난 순서대로 표시하고, 실제 받은 보상만 표시한다. 전투 중 포기는 현재 상대를 실패로 기록하며, 보상 선택 중 포기는 이미 처치한 상대를 실패로 바꾸지 않는다. 상대별 결과도 저장·복구한다. 이 기록을 저장하지 않던 이전 버전의 과거 처치 상대는 이름 기록 없음으로 표시한다.

## 전투와 AI

전투 응답은 결과·체력·상태와 마나·손패를 두 메시지로 나누어 보낸다. 결과의 제목은 방금 해결한 페이즈다. 손패 아래에는 입력 예시·쉬기·포기 안내를 덧붙이지 않는다. 카운터된 카드와 현재 사용할 수 없는 카드·능력은 ❌️로 표시한다. 자동 시전은 원인 카드에서 ⮕로 이어 표시한다. 선택과 로그의 연결 정보도 저장하며, 두 메시지 모두 저장이 완료된 뒤 전송한다. 숫자 입력은 해당 유저가 탐험을 진행 중인 방에서만 처리한다. 예전 코드 포함 명령은 호환을 위해 남겨 둔다.

시작 화면의 제목은 `⚔️ 탐험 1/8 · 0턴 ⚔️`이며, 메인 페이즈와 `대기 중` 줄은 표시하지 않는다. 첫 제출 결과부터 `1턴 · 메인 1`, `1턴 · 메인 2`, `2턴 · 메인 1` 순서로 표시한다. 첫 제출 전에 추가 기본 드로우는 하지 않는다. 마나 증가(5·10·15턴)와 탈진(20턴 시작)은 이 표시 턴을 기준으로 계산한다. 저장된 전투와 예약 효과의 내부 턴 인덱스는 기존처럼 0부터 유지한다.

시작 손패 4장, 기본 손패 한도 8장이다. 펠고지의 지갑은 한도를 10장으로 늘린다. 초과 카드는 제외한다. 스탠바이 → 메인 1 → 메인 2 → 엔드 순서이며 두 메인 페이즈가 마나를 공유한다. 제출 묶음의 비용을 먼저 지불하고, 그 묶음에서 얻을 마나로 다른 카드를 미리 지불할 수 없다.

전투 보상의 카드 추가 선택지는 카드별 가중치를 0~3마나 4, 4마나 2, 5마나 1로 두고 중복 없이 3장을 뽑는다. 이미 보유한 카드는 후보에 포함된다. 발견·무작위 생성·보물 추첨에는 이 가중치를 적용하지 않는다. 이미 제시되어 저장된 선택지는 재추첨하지 않는다.

사용 카드는 효과 해결 후 레스트로 이동하며 덱이 비면 레스트만 섞는다. 해결 중 카드·발견 선택·지연 효과·자동 시전도 저장 가능한 작업 큐에 보관한다. 사망은 양쪽 페이즈 효과 처리 후 판정하며 동시 사망은 탐험 실패다.

끝나지 않는 효과 조합에 대한 안전 규칙도 적용했다. 자동 시전 중 같은 원본 카드로 다시 돌아오는 재귀 호출은 중단한다. 한 번의 해결에서 작업이 2,000개를 넘으면 추가 자동 시전과 반응형 효과를 멈추고 안내하며, 이미 제출한 양쪽 카드의 독립 효과·정리·사망 판정은 계속 처리한다. 이 제한도 발견 도중 저장과 재개에 유지된다.

AI는 공개 체력·마나·상태·영웅·사용 기록과 자기 손패/덱 구성을 사용한다. 상대의 실제 손패, 덱 순서, 제외 카드의 정체, 숨긴 신기루 원본 손패 및 원본 재시작 덱은 읽지 않는다. 공개 기록에서 가능한 상대 카드 구성을 추정하고, 자신의 다음 드로우 순서도 별도로 섞어 실제 셔플 결과를 미리 보지 않는다.

합법적인 카드 조합·영웅 능력·쉬기와 일부 제출 순서를 평가한 뒤, 후보를 실제 전투 엔진의 복사본에서 실행한다. 메인 1은 메인 2의 후속 행동까지, 메인 2는 엔드와 다음 스탠바이까지 비교한다. 카운터를 피하기 위한 보류, 마나 생성과 드로우의 다음 페이즈 활용, 동시 사망 판정, 예약 피해, 보호 효과, 과부하 및 보스의 특수 승리를 반영한다. 더 먼 지속 효과·덱 성장·특수 승리 진행은 별도의 상태 평가로 반영한다. 발견과 속성 선택 역시 현재 체력·덱·공개 사용 경향에 따라 고른다.

판단은 우선 2개 후보와 1개 추정 상황으로 시작한다. 선택지가 하나뿐이면 가상 전투를 생략하고, 차이가 명확하면 초기 비교만으로 종료한다. 점수 차이가 작거나 승패가 걸린 경우에만 최대 4개 후보·2개 추정 상황으로 확장한다. 이미 계산한 결과는 재사용하며 실제 페이즈 실행은 최대 24회, 각 실행의 큐 작업은 최대 360회로 제한한다. 한 번의 AI 계획은 후보 생성과 메인 1·2 가상 실행을 합쳐 최대 5,000ms를 사용한다. 후보 평가·카드 평가·가상 전투 큐에서 시간 제한을 확인하며, 제한에 도달하면 이미 평가한 행동 중 최고 점수 행동을 선택한다. 가상 평가를 하나도 끝내지 못했으면 이미 점수를 계산한 합법 후보를 사용하고, 아직 후보도 없으면 쉰다. 시간 초과 때는 근접 후보 확률 선택을 적용하지 않는다. 같은 결과의 위치 점수와 고정된 현재 상태의 카드 점수는 재사용하고, 발견 선택지의 불필요한 중복 평가는 생략한다. 제한은 AI 계획 시간이며 저장·전송 및 실제 카드 효과 실행 시간은 별도다. 동기식 JS 특성상 진행 중인 단일 연산은 다음 검사 지점에서 중단되므로 약간의 시간 오차가 생길 수 있다. AI 로그에 제한 중단 여부도 표시한다. 모든 행동 순서·무작위 결과·미래 턴을 전부 탐색하는 최적해 보장 방식은 아니다. 계획은 실제 전투 RNG나 원본 상태를 변경하지 않고, 일반 행동은 플레이어 제출 전에 결정하여 저장한다. 예지 효과로 허용된 경우만 현재 공개된 제출에 대응하며 양쪽 예지는 서로 상쇄한다. 단일 JS 파일에 AI 모듈이 모두 포함되며 외부 API는 사용하지 않는다.

이전 최대 48회 방식의 검증 기록(현재 적응형 방식의 속도 수치가 아님): AI 전용 행동·비공개 정보·탐색 한도 검사 17개 통과. 단일 배포 파일을 직접 불러온 18종 보스 × 3개 난수 조건의 54회 전투에서 JSON 저장/복구를 반복했고, 3,859회 판단·84,008회 가상 전투 중 계산 오류와 예산 초과 중단은 0회였다. Node.js PC 환경에서 평균 판단 시간은 약 50ms, 최대 310.3ms였다. Android/Rhino 실기기 속도를 측정한 수치는 아니다.

## 응답 처리 비용

기존 계정의 인벤·도감·덱·도움말·유물·상점 조회는 필요한 정보만 복사하며 저장 파일을 만들지 않는다. 첫 계정 생성이나 열쇠 자동 충전으로 실제 재화가 증가하는 경우에는 저장한다. 일반 채팅·중복 입력 재응답·유휴 타이머도 파일 읽기/쓰기 없이 처리한다. 타이머는 세션 기한만 확인하며 전체 전투 상태를 복사하지 않는다.

Android는 유효한 FileChannel 독점 잠금을 보유한 동안 매 저장 시 과거 파일 목록/최신 사본 재읽기를 생략한다. 새 버전 중복 게시 거부, 두 사본의 동기화 저장, 시작 시 체크섬 검증은 유지한다. SHA-256은 Android Java MessageDigest로 계산하며 Node 및 테스트 환경은 기존 구현을 사용한다. 최근 응답 전문은 문자 예산을 두고 정리하지만 최근 256개 입력 ID는 유지하여 오래된 입력도 중복 적용하지 않는다. 가장 최근 8개 응답은 원문을 보관한다.

처리에 1초 이상 걸리면 앱 로그에 `악질봇4 응답 시간:`으로 잠금 대기·처리/저장·전송 요청 시간을 기록한다. 실제 카톡 화면에 도착하는 시간은 이 수치에 포함되지 않는다. 상태 변경은 여전히 직렬 처리하므로 다른 방의 전투 계산 중 잠깐 대기할 수 있다.

## 저장과 복구

기본 경로는 `sdcard/bot/akjilbot4`다. 2.8.5와 3.1.0의 데이터는 읽지 않는다. 사용자 해시로 방 간 정보를 공유한다. 방마다 다른 해시가 생기면 원래 방에서 `+연동코드`로 5분간 유효한 4자리 코드를 받는다. 다른 방에서 `+연동 [코드]`를 입력하면 `[닉네임]의 데이터로 덮어씌울까요? (y/n)`를 표시한다. `y`는 코드를 발급한 계정으로 연결하고 `n`은 취소한다. 수신 계정에 연결된 해시들도 함께 원본 계정으로 옮긴다. 재화는 합산하지 않으며 교체된 계정은 감사 기록용으로만 보존한다. 확인한 코드는 소모되고, 원래 방에서의 추가 승인은 필요하지 않다. 닉네임만 같다는 이유로 합치지 않는다.

명령을 복사한 상태에서 계산하고, 재화·탐험·선택지·상대 행동·난수·응답 기록을 함께 저장한 **뒤** 응답한다. 변경하지 않는 전체 스냅샷 두 사본, SHA-256 검증, 이전 버전 연결을 유지한다. 임시 파일 기록 → 파일 동기화 → 확정 이름 공개 → 디렉터리 동기화 순서다.

저장 전 종료되면 이전 버전에서, 첫 사본 공개 후 종료되면 그 버전에서 복구한다. 한 사본이 손상되면 다른 사본을 사용한다. 유효한 저장본을 판단할 수 없으면 초기화하거나 덮어쓰지 않고 중단한다. 숫자 입력은 현재 선택 단계에 연결하고 메시지 ID로 동일 메시지의 중복 처리를 방지한다. 새 메시지로 다시 보낸 숫자는 새로운 입력으로 취급한다. 전송 실패로 결과를 재추첨하지 않는다.

Android 시작 시에는 파일명으로 버전 누락을 확인하고 최신·직전 전체 스냅샷의 두 사본과 체크섬 연결을 검증한다. 최신 사본이 모두 손상되면 이전 상태로 되돌리거나 초기화하지 않고 중단한다. 더 오래된 파일 내용의 전체 이력 검증은 기본 Store 로더(개발 검사)에서 수행한다. 초기화 단계는 앱 로그에 기록한다.

스냅샷 이력은 모두 보존하므로 저장 크기가 증가한다. 연결 검증 때문에 과거 파일을 임의 삭제하면 안 된다. 폴더 전체를 별도 위치에 백업할 수 있다. 같은 기기의 두 사본은 기기 분실·저장 장치 전체 고장까지 보호하지 않는다. Android 실제 기기 강제 종료 시험은 이 개발 환경에서 수행하지 않았다.

## 개발 및 검증

src/는 개발용 원본, content/는 원문·설계 자료다. 다음 명령은 개발 PC에서만 실행한다.

```powershell
node akjilbot4/build.js
node --check 악질봇4.0.0.js
node --test akjilbot4/tests/*.test.js
```

운영 설정은 src/live-config.js, 카드·보물·보스는 cards-v3.js, treasures-v3.js, bosses-v3.js, 전투는 combat-v3.js다. 단일 파일을 직접 수정했다면 재빌드 전에 원본에도 반영한다. 기존 버전 파일은 변경하지 않는다.

세부 해석과 추후 필요한 정보는 [입력할 설정](docs/입력할-설정.md)에 정리했다. 기존 설계 문서는 당시 이력이며 현재 상태는 이 README와 입력할 설정을 우선한다.

`+통계` (`+ㅌㄱ`): 누적 속성·카드·보물 선택률/평균 승수와 봇별 격파율. [집계 기준](docs/통계.md).

AI는 메인 1의 전체 사용·쉬기·일부 사용 후보를 비교하고, 각 후보의 메인 2 후속 행동도 최대 2개 비교한다. 메인 2에서 새로 공개된 제출·상태를 반영해 다시 계획한다. 플레이어가 공개적으로 사용한 카드와 쉬기 기록을 페이즈별로 분석하며 최근 48개 페이즈 기록은 다음 전투와 저장소 재시작에도 유지한다. 실제 손패·덱·미공개 발견 선택을 읽지 않는다.

`++재시작`은 관리자만 사용할 수 있다. 명령을 친 방에서 진행 중인 전투를 같은 상대의 조우 화면으로 되돌리고 최신 단계 체력을 적용한다. 전투·발견·예약 효과는 버리지만 승수·탐험 덱·보물·재화와 확정된 상대 덱은 유지하며, 승패나 보상은 기록하지 않는다. 본인의 중단된 전투도 다시 열 수 있다. `y`를 입력하면 새 전투가 시작된다.




일회용 카드는 카운터당하면 제외되지 않고 레스트로 이동한다. 카운터되지 않고 사용되면 제외된다. 카운터 시 제외되는 키워드는 없으며, 식인 꽃의 삼키기 등 별도 제외 효과는 유지한다.

전투 승리 시 남은 현재 체력을 탐험에 저장하여 다음 전투로 그대로 넘긴다. 플레이어의 기본 최대 체력은 모든 단계에서 60으로 고정되며 전투를 넘어가도 증가하지 않는다. 첫 전투는 60/60으로 시작하며, 전투 중 회복 효과는 정상 적용된다.

2026-11-11: 양쪽 시작 마나·최대 마나 2, 탈진 시작은 20턴으로 변경했다. 기존 불안정 키워드는 카드에서 삭제하고 카운터 시 제외 규칙을 폐지했으며, 기존 취약은 새 불안정으로 바꾼다. 신규 키워드의 공통 효과 규격은 [키워드 문서](docs/키워드-2026-11-11.md)를 참고한다. 신규 카드는 아직 추가하지 않았다.

양쪽 방어도는 매 엔드 페이즈의 효과와 정리를 모두 처리한 뒤 0이 된다. 엔드 페이즈 중 획득한 방어도도 다음 턴으로 이어지지 않는다.

현재 직업 명세는 [플레이어 직업](docs/플레이어-직업.md)과 `content/직업-설계.json`에서 관리한다. 거프·사일런트·셀레스테·데칼은 각 10장으로 시작한다. 아감마간도 10장으로 시작하며, 혈석 비용 카드와 손패 내 조건 충족으로 해방되는 혈석 의식을 사용한다. 노틸러스의 시작 덱은 타격 3·투하 2·파묻힌 보물 3·서프라이드 2장이다. 직업 카드는 해당 직업의 전투 보상 풀에만 제공하며, 직업 보물도 해당 직업에만 제공한다. 기존 탐험의 덱을 강제로 교체하지 않는다. 시작 보물은 일반·하급·상급 보물 슬롯과 별도로 적용된다.
